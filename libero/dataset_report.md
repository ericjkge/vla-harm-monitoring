# Dataset report: safety minimal pairs for pi0.5-LIBERO (pilot)

Generated by `generate_pairs.py`, checked by `validate_pairs.py`; every number below is computed from `minimal_pairs_pilot.jsonl` and `validation_results.jsonl`.
Status is **pending human review**; nothing here has been looked at by a person yet.

## 1. What counts as ID / OOD here

- **Ground truth for instruction text:** `physical-intelligence/libero` `meta/tasks.jsonl` (the pi05_libero fine-tuning dataset): 40 tasks, 1693 episodes. Saved in `refs/`. openpi's converter confirms the dataset is built from libero_10, libero_goal, libero_object and libero_spatial only; **libero_90 is not used**.
- **Fine-tuning verbs (task count):** pick up (21), put (16), place (21), open (2), close (2), push (1), turn on (2). Any verb not in those 40 strings is OOD (e.g. `turn off` and `stack` appear only in libero_90; `smash`, `throw`, ... appear nowhere in LIBERO).
- **Objects / scenes:** the dataset's images were not downloaded, so exposure is read from the BDDL scene files of the four training suites (a scene or object is ID if it appears in one of them, including as a distractor). Details and per-item evidence: `libero_distribution.json`.
- **Caveat:** the BDDL instruction text differs from the dataset's text (e.g. "Pick the akita black bowl" vs "pick up the black bowl"), so verbs are taken from tasks.jsonl, not from BDDL.
- **OOD is relative to LIBERO fine-tuning only.** pi0.5 base pre-training and the PaliGemma backbone may have seen all of these words and objects.
- LIBERO has no knives, hands, people or liquids, so classic injury examples (sharp knife in a hand) cannot be built from LIBERO assets alone.

### Condition 1 is empty
no ID verb is harmful by itself: ID verbs ['close', 'open', 'pick up', 'place', 'push', 'put', 'turn on'] are all pick/place/open/close/push/turn-on; harmful ones in the lexicon none. Verb-only harm with both verbs in-distribution would need, for instance, a trained verb that is dangerous on its own; the seven trained verbs are benign, and any hazard from `put`/`push`/`turn on` comes from what is in the scene, which is condition 3 or 5. No pairs were fabricated. Options for the review: (a) accept the gap, (b) allow `turn on` vs `turn off` style pairs (currently condition 2 because `turn off` is OOD), (c) treat `push` as potentially harmful in a push-off-the-table scene (needs a new relation, so not minimal).

## 5. Known confounds and limitations

- **Scene images are not built.** Base scenes can be rendered from `scene.asset_id` (BDDL); every `added_objects` entry and every object swap needs a modified BDDL. (44 pairs use a constructed configuration.)
- **Scene conditions (5, 6) change the image, not the text, and the harmful image has an extra object on the burner.** For condition 6, some pairs also change the layout (harmless and harmful scenes use different layouts), which confounds harm with layout; they are kept because they test ID-to-OOD transfer, and each has a note in `confounds`.
- **Stove-on hazard is stated, not simulated.** LIBERO does not model fire; harm rests on common-sense flammability of paper/cardboard items (medium confidence for cookie box, milk/juice cartons, butter, popcorn, macaroni box; high for books).
- **`turn off` in `stove_item_verb` pairs is close to a no-op** (stove not shown as on).
- **Object pairs change the rendered object, so pixels differ too**; this is intrinsic to an object swap.
- Constructed hazard items are placed in training layouts that did not contain them, so the *configuration* is new even when layout and object are each ID.
- Safety labels come from a hand-written lexicon (`lexicon.py`), and the validator re-derives them from the same lexicon, so it checks consistency, not ground truth. No LLM judge was used. Human review is the real check.
- Single author; no inter-rater check.

## 6. Scaling toward 500

`generate_pairs.py --per-condition N` enumerates every candidate in each family and selects N by diversity. Current enumerable pool per condition: 1 verb: 0, 2 verb: 304, 3 object: 80, 4 object: 80, 5 scene: 20, 6 scene: 72. Candidates are heavily combinatorial copies of two mechanisms, so 500 would be mostly near-duplicates; reaching 500 with real diversity needs new hazard mechanisms (new object pairs, new layouts, more OOD scenes with a stove or microwave) and a decision on condition 1.
